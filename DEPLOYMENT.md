# Обновление существующего GitHub / Render до v0.4

База: main, commit `8b9168517578c74bf6daf7336996e2d10d490488` в https://github.com/Diplo3/AR-Games-Relay (оптимизированная v0.3).

1. Обновить существующий репозиторий содержимым версии v0.4, включая `relay-config.json`. Сохранять структуру public/, test/, examples/. node_modules загружать не нужно.
2. Проверить `npm install` и `npm test` на Node >=20. Зафиксировать изменения в main или объединить проверенный pull request в ветку, которую уже отслеживает Render.
3. Открыть **существующий** сервис Render. Не выбирать New Web Service. Сохранить подключённый репозиторий, URL, тариф, переменные и отслеживаемую ветку.
4. Build: `npm install`; Start: `node server.js` — прежние команды. Если Auto-Deploy включён, дождаться сборки commit; иначе Manual Deploy → Deploy latest commit.
5. На прежнем URL открыть `/health`: version должен быть 0.4.0, maxPhones и maxTeams — по 50, maxCommandsPerSecond — 200. Проверить `/relay-config.json`. Затем проверить HOST/PLAYER, команды TEAM 1 и TEAM 50, восстановление снимка состояния после переподключения, 100/100, включение гироскопа кнопкой на телефоне, смену `endpoints.internet` через манифест и нагрузку до 50 телефонов. Полный локальный прогон описан в `VALIDATION.md`.

Развёртывание может разорвать активные WebSocket-соединения; проводить обновление между играми. Во время испытаний использовать один экземпляр relay: комнаты сейчас в памяти процесса, распределение по нескольким экземплярам не поддерживается.

Откат: в том же Render-сервисе развернуть предыдущий рабочий commit; оставить манифест на конфигурации совместимого relay. Нового сервиса и миграции базы данных не требуется.

После первой интеграции будущая смена relay выполняется в `relay-config.json`; сборка игр не нужна. Не останавливайте прежний relay до подтверждения, что HOST и телефоны уже переключились.
